# Phase 4 CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved bilingual relational CMS, Filament administration, public localized API, controlled asset lifecycle, and deterministic public cache for Phase 4 without implementing the Phase 5 frontend.

**Architecture:** Laravel remains the sole source of truth for managed content. Explicit Eloquent models, typed MySQL tables, closed enums, domain actions, API Resources, an owned-asset lifecycle service, and a central public-content cache service implement the approved contracts. Filament operates through those domain services; public reads are localized, read-only, and limited to `published + visible` data.

**Tech Stack:** Phase 3's PHP 8.5.8 Apache image, Laravel 13.25, Filament 5.7, Livewire 4.4, MySQL 8.4, PHPUnit 12, Laravel filesystem/cache/rate-limiter primitives, Docker Compose, Caddy.

**Spec:** `docs/superpowers/specs/2026-09-02-phase-4-cms-design.md` at approved commit `16f2f68`.

## Global Constraints

- Work only in the existing `feat/phase-4-cms` branch and `.worktrees/phase-4-cms` worktree.
- Use MySQL 8.4 for schema, constraint, concurrency, API, and integration tests; do not introduce SQLite.
- Write the failing test first for every behavior change, run it and record the expected failure, then add only the implementation needed to pass.
- Keep controllers thin and keep public controllers strictly read-only. A public `GET` must never recreate a missing singleton.
- Public controllers are strictly read-only: an abnormally missing Profile or SiteConfiguration returns the controlled `not_found` response and may log safely, but never inserts or repairs content.
- Do not add a generic CMS layer, repository abstraction, translation system, media library, Redis, queues, revisions, soft deletes, preview tokens, SEO, video, or Phase 5 UI.
- Do not expose database IDs, pivot metadata, internal paths, administrative timestamps, `_es`/`_en` columns, or unpublished content.
- Use `TemporaryUploadedFile` with Filament `FileUpload::storeFiles(false)` so normal form persistence cannot bypass the asset lifecycle.
- Use static, bound SQL only where MySQL constraints require it; document every such statement next to the migration.
- Run `./vendor/bin/pint` on touched PHP files before each PHP commit.
- Do not check off Phase 4 in `ROADMAP.md` until the full verification task passes.

## Core Interfaces

The implementation must converge on these explicit interfaces; method names may only change if the same task updates every caller and test.

```php
final class PublicationValidator
{
    /** @return list<PublicationIssue> */
    public function issues(Model $content): array;
    public function assertPublishable(Model $content): void;
}

final class PublicContentCache
{
    public function remember(SupportedLocale $locale, PublicEndpoint $endpoint, Closure $resolver): array;
    /** @param list<PublicEndpoint> $endpoints */
    public function invalidate(array $endpoints): void;
    /** @param list<PublicEndpoint> $endpoints */
    public function withMutationLocks(array $endpoints, Closure $callback): mixed;
    public function key(SupportedLocale $locale, PublicEndpoint $endpoint): string;
    public function lockKey(SupportedLocale $locale, PublicEndpoint $endpoint): string;
}

final readonly class StagedAsset
{
    public function __construct(
        public string $privatePath,
        public string $mimeType,
        public int $size,
        public ?string $publicPath,
    ) {}
}

final class AssetLifecycleService
{
    public function stage(UploadedFile $file, OwnedAssetKind $kind): StagedAsset;
    public function publishPublicCopy(StagedAsset $asset): void;
    public function withdrawPublicCopy(?string $publicPath): void;
    public function restorePublicCopy(string $privatePath, string $publicPath): void;
    public function deletePrivateOriginal(?string $privatePath): void;
    public function publicUrl(?string $publicPath): ?string;
}
```

Sensitive actions run inside an `EditorialMutationContext`; model guards reject direct sensitive transitions outside that context. `PublishContent`, `ShowContent`, `HideContent`, `ReturnContentToDraft`, `DeleteContent`, `ReplaceOwnedAsset`, `ChangePublicKey`, `UpdateExperienceAggregate`, and `ReorderContent` are concrete actions, not modes on a universal service.

## Locked Schema Contract

Every publishable table has `status`, `is_visible`, `published_at`, and timestamps. Its named state check enforces draft→hidden/null timestamp and published→non-null timestamp. The six keyed tables also have required ASCII slug `key`, irreversible `key_locked`, nonnegative non-unique `position`, `UNIQUE(key)`, and the check that published implies `key_locked=true`.

| Table | Exact domain columns beyond IDs/timestamps/common editorial columns |
|---|---|
| `profiles` | `singleton_key`; nullable `name`; `headline_es/en`, `short_summary_es/en`, `introduction_es/en`, `availability_es/en`, `cta_es/en`; `photo_private_path`, `photo_public_path`, `photo_mime`, `photo_size`, `photo_alt_es/en` |
| `site_configurations` | `singleton_key`; `projects_empty_message_es/en`, `contact_intro_es/en`; `technology_{backend,data,integration,collaboration}_label_es/en` |
| `experiences` | `key`, `key_locked`, `position`; `role_es/en`, `summary_es/en`; optional pair `organization_label_es/en`; `start_year`, `start_month`, `end_year`, `end_month` |
| `experience_highlights` | `experience_id`, `content_es`, `content_en`, `position`, timestamps; no editorial columns |
| `work_cases` | `key`, `key_locked`, `position`; `title_es/en`, `context_es/en`, `problem_es/en`, `contribution_es/en`, `technical_approach_es/en`, `outcome_es/en` |
| `projects` | `key`, `key_locked`, `position`; `title_es/en`, `summary_es/en`, `problem_es/en`, `solution_es/en`; `featured`; `demo_url`, `repository_url`; `image_private_path`, `image_public_path`, `image_mime`, `image_size`, `image_alt_es/en` |
| `technologies` | `key`, `key_locked`, `position`; untranslated `name`; closed `category`; `icon_private_path`, `icon_public_path`, `icon_mime`, `icon_size` |
| `expertise_areas` | `key`, `key_locked`, `position`; `title_es/en`; optional pair `description_es/en` |
| `work_principles` | `key`, `key_locked`, `position`; `statement_es/en` only |
| `professional_links` | unique closed `type`, `position`, `destination`, `label_es/en` |
| `cv_documents` | unique immutable `locale`, locale-specific `label`, `private_path`, `mime`, `size` |
| `experience_technology` | `experience_id`, `technology_id`, `position`, unique FK pair |
| `technology_work_case` | `work_case_id`, `technology_id`, `position`, unique FK pair |
| `project_technology` | `project_id`, `technology_id`, `position`, unique FK pair |

Required-for-publication content stays nullable where a draft may be incomplete. Structural keys, closed domains, link destination, and Experience start year/month remain non-null. Narrative columns are `TEXT`; public keys are ASCII `VARCHAR(100)`; singleton keys `VARCHAR(32)`; URL/path fields use the approved bounded lengths; sizes are unsigned bigint; positions unsigned integer; years/months use the approved unsigned types and checks. Asset private path/MIME/size groups are all-null or all-present, and a public path requires a complete private group plus `published + visible`.
